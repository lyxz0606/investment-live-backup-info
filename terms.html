Investment Live Private Backups

Personal-use Terms

This tool is maintained solely for the owner's private backup workflow. It is not a hosted backup service offered to other users. This page does not create an account, accept payment, or start any database operation.

Authorization and scope

Only the owner may authorize the configured Google account and private backup destination. Authorization is limited to the requested drive.file permission and may be revoked at any time. Publishing these pages is not authorization to export production data or enable daily backups.

Database exports must use the approved backup identity. A backup operation must not alter production investment positions, trades, or rules. Restoration is permitted only in an explicitly approved isolated environment, never against the current production database.

Owner responsibilities

  • Keep the decryption private key and its offline recovery copy protected and outside cloud backup execution.
  • Review the actual export scope, encrypted-file integrity, storage results, and recovery tests before enabling production schedules.
  • Monitor free-service limits, OAuth authorization health, storage capacity, and backup freshness.
  • Do not put credentials or unencrypted exports in public repositories, workflow logs, or this information site.

Limitations

A database logical backup is not a complete backup of the entire cloud platform. Storage object files, deployed functions, website deployments, and secret configuration can require separate recovery arrangements.

Free cloud services and schedules can fail or be delayed. Encryption cannot compensate for a lost private key or an incomplete export. A successful workflow run alone does not prove that a restorable cloud backup exists.

No uninterrupted service, data recovery, investment outcome, or financial return is guaranteed. The tool does not provide trading advice or place orders. Third-party services remain subject to their own applicable policies.

Changes and retirement

Permission changes, production activation, and destructive retention changes require explicit owner approval. Retiring the tool includes disabling its schedules, removing cloud credentials, revoking Google access, and separately deciding what retained backups to keep.
